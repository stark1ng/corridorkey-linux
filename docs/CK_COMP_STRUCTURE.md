# Структура Fusion-композа CorridorKey

Проверено на 21.1 (4K, Deliver-рендер 4096×2160): композ собирается вставкой готового
текста в граф, ноды стоят компактно, фон подставляется, зелёного не остаётся.

## Граф (рабочая структура, 4 ноды)

```
ck_bg      (Loader, PNG-секвенция фона)      ─┐
                                              ├─► ck_merge (Merge) ─► MediaOut1
ck_subject (Loader, RGBA-вырезка, EXR/PNG)   ─┘
```

| нода        | тип      | Pos (x, y) | входы                                   |
|-------------|----------|------------|-----------------------------------------|
| ck_bg       | Loader   | 0, 130     | Clip = PNG-секвенция фона, 0…N−1        |
| ck_subject  | Loader   | 0, −130    | Clip = RGBA-секвенция (cutout), 0…N−1   |
| ck_merge    | Merge    | 260, 0     | Background ← ck_bg, Foreground ← ck_subject |
| MediaOut1   | MediaOut | 480, 0     | Input ← ck_merge                        |

`MediaIn1` в композе клипа уже даёт кадр таймлайна, отдельный нод для плашки не нужен.
`Loader` не читает mp4 — все видео-результаты предварительно перегоняются в PNG
(`_to_sequence`), фон-картинка тоже становится секвенцией длиной в плашку.

## Альфа: почему `fg` нельзя подавать в Merge напрямую

`fg_*.exr` из CorridorKey пишется **с alpha = 1** (непрозрачный), настоящая масть лежит
в отдельной `alpha_*.exr`. Если подать `fg` в Foreground, он перекрывает фон целиком и
в рендере получается «субъект на чёрном». Поэтому в граф идёт:

- `cutout_*.exr` — RGBA с настоящей альфой (предпочтительно), либо
- RGBA, собранный `ffmpeg`-ом из `fg` + `alpha` (`prepare_rgba`, фильтр `alphamerge`).

MatteControl с `Garbage.Matte` в 21.1 через вставку текста нормальную маску не даёт
(в одном варианте убивает субъект, в другом не применяется), поэтому он из структуры
убран.

## Как собирается

`resolve_compose.py --job <id> --bg <картинка|видео>` (по умолчанию — вставка):

1. `_to_sequence` готовит PNG-секвенцию фона длиной в плашку;
2. берётся `cutout`, иначе `prepare_rgba(fg, alpha)`, иначе PNG из видео-результатов;
3. на странице Fusion чистятся прежние `ck_*`/`MediaOut`;
4. текст композа (`resolve/compose_template.py`) кладётся в X11-буфер и вставляется
   `comp.Paste()` — ноды появляются компактно со всеми связями;
5. проверка — только Deliver-рендером: у градиента `--bg4k` средний BGR ≈ (126, 80, 106),
   у «субъект на чёрном» ≈ (13, 2, 6), у «только фон» ≈ (128, 87, 113).

Старый путь через `AddTool`/`SetInput` остался под флагом `--api`: он работает, но
раскидывает ноды на десятки тысяч пикселей и через раз теряет связи.

## Что нельзя делать

- `AddTool(regid, x, y)` — координаты в других единицах (1 ≈ 14 600 px).
- `comp.Save()` без аргумента — открывает диалог «Save File» и вешает скрипт;
  сохранять `projectManager.SaveProject()`.
- `ImportFusionComp()` для композа с `Loader` — Resolve конвертирует лоадеры в `MediaIn`
  и внешние файлы теряются.
- Править ноды через Fusion API при открытом 4K-композе: каждый `SetInput` вызывает
  пересчёт 4K и вешает скрипт на минуты. Для 4K — только вставка текста целиком.
